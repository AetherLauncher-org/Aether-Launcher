# 账户与凭据

`aether-auth` 负责把用户带到正版 Minecraft 账户上：走微软设备码登录、把令牌链一段段换到 Minecraft 访问令牌、再从 profile 读出玩家名，最后把凭据安全地落到磁盘。这篇讲实现时绕不开的概念与取舍，不列具体类型和函数签名——名字以代码为准。

## 设备码登录

登录走 OAuth 2.0 设备码流程：用户在浏览器里输码确认，启动器不内嵌登录页。好处是不必跟随微软登录页的改版，也不用在 WebView 里接触密码；代价是轮询期间启动器必须能容忍用户什么都不做。

```text
申请设备码（device code + user code + 有效期）
  → 展示 user code，用户在浏览器登录并授权
  → 轮询令牌端点，直到授权 / 过期 / 拒绝 / 取消
  → 用微软令牌换 Xbox Live 令牌（XBL）
  → 用 XBL 令牌换 XSTS 授权
  → 用 XSTS 授权换 Minecraft 访问令牌
  → 用访问令牌读 profile，得到玩家名与 UUID
```

四条不能改的行为：

- **轮询间隔由服务端给。** 申请码的响应里带 `interval`，等待时间以它为准，代码里不写死 sleep 时长。间隔偏短会触发限流，返回的错误码看起来像登录失败；间隔偏长只是慢，不会出错。设备码过期后重新申请一张，不要复用。
- **链条中间段过期不代表前段失效。** XBL、XSTS 与 Minecraft 令牌各有自己的有效期，刷新时从**最早失效的那一环**重新走：Minecraft 令牌过期只需重换后半段，微软访问令牌过期则先用刷新令牌换新的访问令牌再走。只要刷新令牌还有效，用户不需要重新输码。
- **profile 是拿玩家名的唯一位置。** 登录链条本身只产出令牌。玩家名与 UUID 只能通过读 profile 得到；读不到 profile 就当登录未完成，不要拿邮箱、Xbox 显示名或上次缓存的名字凑一个账户。
- **取消是正常路径。** 用户在轮询期间点取消，结果是一个独立的「已取消」状态，不是错误：不弹错误提示、不写日志 WARN、安静回到未登录状态，下一次登录从申请码重新开始。

设备码响应里除 `interval` 外还有 `expires_in` 与 `user_code`；把用户码的剩余有效期显示出来，比只显示一个「等待中」更不容易让人放弃。**待实现确认**：轮询在后台线程还是由前端驱动、取消信号如何传到轮询循环，取决于最终的 IPC 形态。

## XBL / XSTS 错误码

XSTS 阶段返回的服务端错误码，是用户能自行处理的那一类。它们与网络错误（超时、断连、DNS 失败）必须分开呈现：前者给一句可以照着做的话，后者给「检查网络后重试」。

| 错误码 | 含义 | 启动器应当怎么说 |
| --- | --- | --- |
| `2148916233` | 该微软账户没有创建 Xbox 档案 | 「这个微软账户还没有 Xbox 档案，需要先在 Xbox 官网创建后再登录」。给一个可点击的链接，不要让用户自己去搜；创建完成后重新登录即可，不必重启应用 |
| `2148916235` | Xbox Live 在该地区不可用 | 「Xbox Live 在您所在的国家或地区不可用，启动器无法绕过这个限制」。不要建议换网络或换账号重试，同时提示可以改用离线账户启动 |
| `2148916238` | 账户被判定为未成年人，需要家庭组成人账户同意 | 「这个账户需要在微软家庭设置里由成人账户批准后才能登录」。说明批准后要重新发起登录，启动器不会自动重试 |

两条实现约定：

- **错误码按 `u64` 匹配。** `XErr` 可能以 JSON 数字或十进制字符串出现，两种形态都要接受；按 `u64` 解析，部分取值超出 `i32` 范围，转成窄整数再查表容易在转换或比较上出错。按当前实现：解析只保留数值，响应体与随附的重定向 URL 一并丢弃。
- **未知码保留原始数值，不当解释用。** 按「未知错误 + XSTS 错误码」呈现，便于排查，但不要把它当成用户能理解的说明。

## 令牌脱敏

令牌可能在四个地方被看见：日志、错误信息、界面上「当前账户」的调试信息、以及序列化输出。规则按暴露面分三档：

- **日志与错误信息：完全不出现。** 完整令牌不出现，令牌前缀也不出现——前缀足以在别处定位到同一个会话。需要定位时只记阶段名、HTTP 状态码与令牌长度。
- **调试输出：只显示尾部 4 位。** 形如 `RefreshToken(****1234)`，冒号前是凭据类型标签，星号是固定宽度，不随真实长度变化（长度本身也是信息）；不足 12 字符时整体隐藏，连尾部也不留。
- **刷新令牌永不显示。** 任何级别日志、任何错误路径、任何调试视图都不例外。它比访问令牌活得更久，没有任何排查场景需要看到它。

**相关类型的 `Debug` 要手写。** `derive(Debug)` 会把字段原样打出来，含令牌的结构体一旦被临时 `{:?}` 打印，脱敏规则就全线失效；`Display` 同理。按当前实现：`HttpRequest` 与 `HttpResponse` 的 `Debug` 都只报长度、不报内容，敏感请求头按名替换为占位；凭据存储侧唯一持有明文的是私有的落盘结构，它不实现 `Debug`。**待实现确认**：实例记录等上层结构里是否还有绕过脱敏 newtype 的裸 `String` 字段，需要逐个核对。

错误信息里的响应体同样要处理：服务端回显的局部令牌一律不拼进错误字符串，只保留错误码与阶段名。

## 凭据存储

存储由一个 trait 表达，实现负责落盘。这样测试可以用内存实现、不碰用户目录，将来接系统密钥环时也只换实现。

写入走的协议与[实例记录](instance-lifecycle.md)那个文件的写法一致：**同目录下写临时文件，再 rename 覆盖目标**。中途崩溃或断电只会留下完整的旧文件或完整的新文件，不会读到写了一半的 JSON。临时文件必须与目标同目录，跨卷 rename 不是原子操作。

安全边界：

- **磁盘上绝不以明文存储 refresh token。** `FileCredentialStore` 无持久化刷新令牌的配置开关，只保存账户元数据；内存中的刷新令牌会被剥离。需要跨重启保存刷新令牌时，使用 `KeyringCredentialStore`，它只将元数据写入 JSON，令牌保存在系统凭据库。凭据库不可用时返回错误，不回退为明文。
- **账户标识与显示名可以明文。** 它们不是凭据，读列表时不需要解密；玩家名与 UUID 也允许明文，便于离线浏览账户列表。
- **文件限定在应用数据目录内。** Windows 没有 POSIX 权限位，实现依赖该目录的默认 ACL，不额外争取更强的保护。

### 系统凭据库与局限

`KeyringCredentialStore` 使用 Rust `keyring` 对接 Windows Credential Manager、macOS Keychain 和 Linux Secret Service。JSON 文件只保存账户元数据；系统凭据库的条目用 Aether Launcher 专用服务名和账户 UUID 定位。系统凭据库拒绝访问、未解锁或不可用时会明确报错，不会写入明文替代文件。

操作系统凭据库防止意外文件泄漏，但无法阻止同一已登录用户权限下的恶意软件或注入本进程的攻击者。不要把它描述为防止所有本机恶意软件。账户注销对微软账户先删除 OS 凭据、再删除元数据；对离线账户只删除元数据，不依赖 OS 凭据库。两种存储不构成原子事务，失败会显式报告，允许安全重试；若 OS 凭据已写入但元数据写入失败，可能留有孤立的保险库条目，可通过同一账户 ID 重试覆盖。保险库中格式损坏的凭据单独报告为内容损坏，错误信息不包含令牌。

旧版本如果已经生成带 `refresh_token` 的明文 JSON，当前文件读取器会拒绝，**不会自动迁移明文密钥**。用户可删除旧凭据后重新登录，避免明文迁移期间意外暴露。

文件中的账户标识仍可被读取；不存在跨设备同步 Token。Linux 桌面环境需要可用且已解锁的 Secret Service 服务。

## 不变量

1. 没读到 profile 的登录不进入可用状态，账户名不来自推测。
2. 轮询间隔取自服务端，代码里没有写死的等待时长。
3. 令牌不出现在日志、错误信息、`Debug` / `Display` 输出与界面文本里；刷新令牌在任何路径上都不显示。
4. 凭据落盘一律走临时文件 + 同目录 rename。
5. 退出登录后凭据文件不存在。
6. 测试不访问真实微软 / Xbox / Mojang 接口，网络与存储都通过 trait 替身完成。

## 不做什么

- **不做内嵌网页登录。** 不接管密码、不读登录页 DOM、不保存会话 cookie；微软登录页的改版与启动器无关。
- **不自行重试 XBL / XSTS 错误。** `2148916233`、`2148916235`、`2148916238` 都是需要用户去别处操作的状态，自动重试只会刷屏并再次失败。
- **不跨设备同步凭据。** 不提供导入导出令牌的入口，凭据只在本机的应用数据目录里有效。
- **不用 token 换玩家名。** 令牌链中途返回的标识（账户 id、XUID 之类）不等于玩家名，只有 profile 里的名字用于显示。
