# 拖放安装

后端 `aether-app::drop` 接收原生监听器提供的文件路径；网页只收到 `{token, items: [{name, size, kind}]}`。令牌两分钟后过期，安装时只能使用一次，最多保留 32 个待确认的拖放。任一文件不符合条件时整批拒绝。每批最多 20 个普通文件，每个不超过 256 MiB；文件夹、链接、`.mrpack` 和未知类型不接收。

`.jar` 是模组。`.zip` 只检查最多 100,000 个压缩包条目的名字，不解压：根目录的 `pack.mcmeta` 加 `data/` 为数据包，加 `assets/` 为资源包；没有 `pack.mcmeta` 且含 `shaders/` 为光影。若数据和资源同时存在，数据包优先。其他 zip 拒绝。

确认界面选择实例；数据包可选择多个世界。游戏运行时不能安装。复制按 64 KiB 分块，检查源文件大小，用独占创建占住目标名并通过临时文件放置；同名文件跳过，结果逐项报告。目标目录及祖先检查链接和 Windows 重解析点；源文件重新检查。目录检查与使用之间不能抵御其他本地进程并发替换目录。

原生监听器尚未接入，当前应用不能实际接收拖放。默认 Tauri 拖放处理器已关闭，避免把路径发送到网页。开发时 `?mock=drop` 模拟不含路径的预览，Rust 测试可直接向 `stage` 提供路径；桌面开发构建另有 `simulate_dev_drop` 命令——把环境变量 `AETHER_DEV_DROP` 指到一个文件夹，在 DevTools 控制台执行 `__TAURI_INTERNALS__.invoke('simulate_dev_drop')`，后端就替监听器把这个文件夹里的普通文件走一遍完整流程（路径仍不经过 IPC，发布构建里命令直接拒绝）。真实原生接入的待办见 [下一批功能](../design/next-features.md)。
