# 实例管理

实例页点「管理」进入单个实例的管理页：详情、改名、删除、内容（模组、资源包、光影、存档、Litematica 投影）、日志、打开文件夹、这个实例自己的内存。这篇讲它怎么划边界、前后端各管什么、哪些还没做。

## 游戏目录

游戏在实例自己的 `minecraft/` 里运行（`<实例>/minecraft`），存档、模组、资源包、光影、配置、日志和崩溃报告都在那里，`instance.json` 旁边不放游戏文件。这和 [实例生命周期](instance-lifecycle.md) 写的布局一致。早先启动器把实例根目录当游戏目录，已经启动过的实例会在下一次启动时把 Minecraft 自己的那几项固定名单从根目录移进 `minecraft/`（只移普通文件和文件夹，不跟随链接，目标已存在就不动）。

管理页只认这个目录。

## 边界

- **前端不传路径。** 文件夹用固定标签指定（`mods`、`resourcepacks`、`shaderpacks`、`saves`、`schematics`，以及 `game`、`logs`、`crash-reports`），单个文件用**纯文件名**指定（一个普通的路径分量：不含分隔符、`..`、`:`、控制字符，不以点或空格结尾，最长 255 字节）。后端按已校验的实例记录解析出真正的位置（`aether_storage::manage`）。
- **链接既不列出也不跟随。** 内容文件夹里的符号链接和 junction 被忽略；删除和开关遇到链接直接拒绝。
- **每次遍历都有上限。** 单个列表最多 2000 项，量大小最多走 20 万个条目、40 层。
- **内容文件不执行也不打开。** 列表只读文件名和大小（世界多看一下 `level.dat` 在不在），不解压模组、不解析 NBT。
- **运行中的实例不能改文件。** 删除实例、开关模组、删除内容在游戏运行时被后端拒绝，界面同时置灰并说明原因。
- **打开文件夹**交给操作系统的文件管理器，路径由后端拼出，打开前确认它真的在实例目录里（挡掉内容文件夹名字上被放了链接的情况）。

## 命令

| 命令 | 作用 |
| --- | --- |
| `instance_details` | 名称、版本、加载器（从版本 id 推出）、游戏目录大小、每类内容的数量。不含任何路径 |
| `rename_installed_instance` | 改显示名，目录名（UUID）不变 |
| `delete_installed_instance` | 删掉实例自己的目录和它在共享游戏树里解出的 natives；共享的 `versions`、`libraries`、`assets` 不动 |
| `list_instance_content` | 列出一类内容：名字、大小、是否启用、是不是文件夹 |
| `set_instance_mod_enabled` | `x.jar` ↔ `x.jar.disabled` |
| `remove_instance_content` | 删除一项（文件，或世界这样的整个文件夹） |
| `list_instance_logs` / `read_instance_log` | 最近一次日志和崩溃报告；只读末尾 256 KiB，且已脱敏 |
| `open_instance_folder` | 在文件管理器里打开某个标签对应的文件夹，不存在就先建 |

## 日志的处理

日志和崩溃报告是不可信输入，里面可能有玩家名、UUID、令牌片段、邮箱、IP 和用户目录。后端读的时候只取末尾 256 KiB（不读整个文件），把非 UTF-8 字节替换掉，再过 `aether_diagnose::redacted`，界面拿到的和「复制」出去的都是脱敏后的文本。

## 内存覆盖

每个实例可以「只为这个实例设置」内存上限，默认跟随设置页里的全局值（自动或自定义）。覆盖存在本机的 `localStorage`（键 `aether.instance.<id>`），和全局的内存设置放在同一个地方，不进实例记录；删除实例时一并清掉。启动时前端把解析出来的数字作为 `memoryMib` 传给后端，和以前一样。

## 待定

- **每个实例选 Java。** 设置页里选的 Java 目前**不影响启动**：后端按游戏要求的主版本自己从扫描结果里挑。要让「全局 / 每个实例选 Java」真的生效，前端得告诉后端选哪一个，而 [启动与进程](../design/launch-and-process.md) 规定前端不传 Java 路径，`launch.test.ts` 里也有一条测试守着这个。比较稳妥的做法是后端给每个扫描到的 Java 发一个不透明的 id，前端只存和回传 id，后端在自己扫描到的列表里按 id 查（找不到或主版本不符就自动挑）。这改动设置页和启动命令的契约，需要先定，所以这一轮没做。
- **模组信息。** 列表现在只有文件名和大小。读 `fabric.mod.json` / `mods.toml` 里的名字、版本、图标要打开不可信的 jar，需要先定大小和条目上限，以及放在哪一层。
- **投影的子文件夹。** Litematica 的 `schematics/` 允许建子文件夹，这里只列最上层的文件。
- **导入内容、搬运存档、导出整合包。** 不在这一轮。
- **复制实例。** 需要决定要不要带存档，也要避开同名冲突，没做。
