# 崩溃分析

`aether-diagnose` 只做**本地、确定性**的解析 / 分类 / 脱敏 / payload 组装，**不做任何网络 IO**。它不知道窄接口有多少额度，也不知道 AAPI 的地址，更不知道 Cosy 网关在哪里：这些都在调用方和另一侧。所有逻辑用固定样本可复现测试，同一输入永远得到同一输出。这条边界比 crate 里任何一个函数都重要——本文剩下的部分都在解释它怎么维持。

产品流程、界面、服务端窄接口与 Cosy 第二层脱敏见[设计篇](../design/crash-analysis.md)，本文不重复。

## 内部模块分工

六个模块，依赖方向单一：`evidence` 是唯一输入，`payload` 是唯一输出，中间四个都是纯函数。

| 模块 | 职责 | 是否读文件 |
| --- | --- | --- |
| `evidence` | 单次启动的证据采集模型与切分规则 | 否，只接收调用方读到的内容 |
| `phase` | 失败阶段判定 | 否 |
| `classify` | 本地规则分类，结果带可信度 | 否 |
| `javatab` | JVM 参数 → 最低 Java 版本，启动前预检 | 否 |
| `redact` | 第一层脱敏，占位符与还原 | 否 |
| `payload` | 服务端 payload 组装、缓存签名、预览文本 | 否 |

**`evidence`** 建模的是「单次启动」，不是整份日志。调用方在拉起进程前记一次长度与最新时间戳，进程退出后再记一次，本模块只从两次快照推导出属于本次启动的部分：`latest.log` 按字节长度切尾巴，能处理「追加」「被轮转后变短」「本次新建」三种真实情形，切点落在字符中间时前移到边界而不是 panic。崩溃报告与 `hs_err` 只按文件名模式认领，不符合 `crash-YYYY-MM-DD_HH.MM.SS-<side>.txt` 或 `hs_err_pid<digits>.log` 的名字直接丢弃，这样目录里上一个实例留下的旧文件不会被算进本次证据。模块本身不碰文件系统，路径也不进模型，目录只用名字描述。

**`phase`** 决定「这次失败发生在哪一步」，并且在设计篇的阶段表之外补了两条：崩溃报告优先于 JVM 启动失败（窗口创建阶段崩溃也可能留下报告，报告是更具体的证据）；退出码只是输入之一，进程跑得久、写得多时，即使拿不到退出码也从输出判定。它只看一个投影出来的摘要——退出码、时长、输出字节数、有无新报告——不看日志正文，因此判定依据那几句中文说明里不可能夹带日志文本。判定不出来的情形落到 `Unknown`，这是对不可信输入唯一安全的答案。

**`classify`** 是本地规则表，按优先级取第一条命中的，命中即给出原因、可信度和建议动作。建议动作是启动器认识的固定几种（换 Java、加内存、禁用某个 mod、重装版本、导出诊断包、查看日志），不是自由文本。可信度只有高、中、低三档：本地规则命中给高；参数确实在命令行里出现过、但表里没有它的最低版本要求时降为中。

**`javatab`** 维护「参数 → 最低 Java 版本」的离线表，供启动前预检使用，因此「参数比选中的 Java 新」不必等到崩溃才发现。查表先精确匹配再按最长前缀匹配，`-XX:-Foo` 与 `-XX:+Foo` 视为同一项。它的设计原则是保守：**表里没有的项永不告警**，选中的 Java 版本未知时也不告警——宁可漏报，不可误报。表的来源与维护方式见设计篇「待定」。

**`redact`** 是第一层脱敏，只处理结构确定的敏感项，详见下文。它同时产出占位符映射（同一原值在整个文本里映射到同一个编号）和一份按类别计数的报告，报告供预览界面显示「替换了几处」。占位符可以还原，但还原只在本机有意义，不外发。

**`payload`** 负责两件事：抽出要外发的段落并给出预览；对异常类、栈顶几帧和相关 mod 集合做归一化后算出缓存签名。抽查段落有总字节预算，超出时标 `truncated` 而不是静默截断。缓存与签名的规则见设计篇，这里只说一点：签名不取脱敏后的文本，取的是归一化结构——异常类名、去掉行号与 lambda 编号的栈帧、从栈帧里提取的 mod 名 token。因此它不随占位符编号变化，也不受日志里其他噪声影响。

## 日志是不可信输入

日志里含 mod、服务器、聊天写进去的文本，可以做提示词注入。本 crate 的处理方式是结构性的，不依赖「模型会听话」：

- 日志片段只作为**结构化字段**传递。JSON 里它们是独立的数组元素，与阶段、退出码、Java 版本这些机器生成字段平级，绝不拼进任何被当成指令阅读的位置。任何声称自己是「系统提示」「上文已结束」的行，都只是某个数组里的一个字符串。
- 渲染时一律纯文本：不解析 markdown、不渲染链接、不把日志内容拼进任何会被当作格式解析的位置。抽取时会去掉 ANSI 转义并截断超长行，控制字符不进证据行。
- 模型输出只当**建议**。每一条建议都要用户逐步确认，不自动执行任何动作，包括「禁用某个 mod」这种看起来无副作用的动作。
- 建议动作限定为启动器认识的几种。模型给不出已知动作名时，这条建议作废，不降级成自由文本指令。

一个尚未闭合的点：`classify` 从日志里抄出的 mod 名会被放进「禁用某个 mod」这个动作的目标里。日志不可信，所以这个名字也不可信，执行前应当拿本地 mod 列表核对一遍——目前没有做，标注为待实现确认。

## 第一层脱敏为什么不追高熵

高熵检测会把 mod id（`micdoodle8`、`xaerobetterpvp`）、SHA-1、十六进制地址、贴图尺寸（`512x256x4`）一并替换掉，而这些**恰恰是诊断最需要的信息**。mod 名被换成占位符之后，模型看到的是「某个 mod 崩了」，等于没看到。设计篇记录了在 92 份真实样本上的本地评估：高熵检测的 435 次命中里，除了 SHA-1/MD5 与十六进制地址，还包括大量 mod 标识和贴图尺寸；邮箱检测的 461 次命中里，459 次是加载器版本串，其余 2 次同样是 `mod@版本`，整批样本里没有一封真邮箱。结论是不开默认的全开。

所以第一层只处理 MC 特有、结构确定的项：

- 按位置的启动参数：`--accessToken`、`--refreshToken`、`--clientToken`、`--username`、`--uuid`、`--xuid`、`--clientId`、`--userProperties`。识别依据是参数名后面的位置，不是值的形状，因此长度、字符集都不影响判断。
- 路径中的用户名：`C:\Users\<名字>\`、`/home/<名字>/`、`/Users/<名字>/`，只替换用户名那一段，盘符与 Home 前缀保留。
- 玩家名、UUID 与电脑名：没有按形状匹配的规则，只覆盖它们「作为上面那些参数值或路径段出现」的情形。设计篇要求的三项里，脱离参数与路径独立出现的玩家名、UUID、电脑名目前不处理，标注为待实现确认——加规则容易误伤，加之前要先有样本。
- 服务器地址：带端口的域名直接替换；裸域名只在紧跟在 `connecting to` 之后时替换，且跳过 mojang、fabric、forge、neoforge 等官方域。
- 邮箱：**排除 `模块@版本` 形态**。`cpw.mods.modlauncher@10.0.8` 这种左边是多段全小写包名的、以及右边全是数字与分隔符的，都不当邮箱。
- 额外两类意外收获：`Bearer` 后面的令牌和形如 JWT 的长串。

为了不误伤诊断信息，还有几条硬性的跳过规则：以 `.java`、`.jar`、`.toml` 等文件后缀结尾的 token 不当主机名；栈帧行里的 `文件:行号` 不受服务器地址规则影响。这两条是必须的——栈帧是整份日志里最有用的一段，误替换它比漏替换一个 IP 的代价高得多。

**留在日志里的信息是有意保留的**：mod 列表、版本号、Java 版本、系统信息、异常栈。外发前必须让用户看到实际内容，这一层不替用户做「大概没问题」的判断。

## 不在本仓库范围

- **服务端窄接口**：鉴权、限流、固定 prompt、模型选择都不在这里。本 crate 只保证送出去的 payload 是结构化的、脱敏过的。
- **AAPI 客户端**：不在这里，并且放在 trait 后面，以便本地测试不碰网络。
- **Cosy 第二层脱敏网关**：不在这里，也不由客户端直连。
- **AAPI 不可用时**：只展示本地分类结果，不做降级重试，也不提示用户「稍后再试」——本地答案本身就是完整答案的一种。

## 不变量

1. **任何网络 IO 都不在本 crate 内。** 没有 HTTP 客户端依赖，没有 socket，没有异步运行时。
2. **固定样本可复现。** 同一输入同一输出：规则按优先级取第一条、证据按固定顺序拼接、抽取按固定谓词、签名按排序去重，都不依赖哈希表迭代顺序或时间。
3. **脱敏后的内容外发前必须展示给用户。** 预览与实际 payload 出自同一次脱敏，预览里看到什么，发出去就是什么。
4. **日志文本永远不进入可执行路径。** 它只会成为结构化字段里的字符串、纯文本渲染的一行、或缓存签名的一个输入；不会变成动作参数而不经核对（见上文待实现确认处）。
5. **阶段判定不读日志正文。** 它只看摘要，所以判定依据不能被日志内容左右。
6. **未命中即承认未命中。** 阶段判不出是 `Unknown`，规则没命中就返回空，本地可信度不够才建议外部分析——不编造一个低置信度的结论凑数。
