# 原生界面

记录从 Tauri + React 外壳改成原生界面的决定、顺序和验收条件。**这份文档与 [ui-shell.md](ui-shell.md) 冲突的地方以这份为准**（ui-shell.md 描述的是现在的 React/Fluent 外壳，原生界面做完、替换掉它之后再删）。

## 决定

2026-10-31，项目负责人决定：**界面改成原生的，不再用 Tauri**。工具包先不定，做一轮对比后再选。

## 为什么

- 三个系统用三个渲染引擎（Windows 的 WebView2、macOS 的 WKWebView、Linux 的 WebKitGTK），行为不一致；WebGL 的 3D 预览在 WebKitGTK 上最不可靠。
- 网页不能控制渲染引擎里自带的界面。例子：抓取鼠标时 WebView2 会弹「按 Esc 显示光标」，网页关不掉。
- 3D 预览要「按显示器刷新率走、1 核 1 GB 的集成显卡也不掉帧」。浏览器里 `requestAnimationFrame` 跟着垂直同步，画不快过显示器，内存基线也高；原生可以直接用 wgpu。
- 体积不是用户在意的事，所以 Tauri 最大的优点用不上。

## 不变的

- **Rust 核心不动**：`aether-*` 各 crate 没有任何 Tauri 代码，原样保留。
- [启动与进程](launch-and-process.md) 里的安全约束一条不放宽：界面只能通过窄的、登记过的操作调用核心；不加「执行任意命令、读写任意路径」的入口；凭据不进日志、序列化和界面；下载只信官方清单；清单、日志、崩溃报告、投影文件都是不可信输入。
- Apache-2.0：选工具包时许可证要兼容（不能把 GPL 链进来）。

## 顺序

1. **把业务逻辑从 `src-tauri` 搬进 `aether-app`**（启动与进程里早就写了这一层）。它不依赖任何界面：需要的外部能力（数据目录、某个实例的游戏是否在运行、之后还有事件推送）由一个 `Host` trait 提供。`src-tauri` 退化成「参数转换 + 调 `aether-app`」。这一步对 Tauri 版和原生版都有用，每搬一块，应用都还能正常运行。
2. **做一轮对比**，在两个候选工具包上各做同一个小范围：实例列表、一个有中文输入框的表单、3D 预览。比：中文输入法（IME）、外观、帧时间、内存、编译体积、许可证。结论写回这份文档。
3. **逐页重写**原生界面，页面对页面地对照现在的 React 版。
4. **替换**：功能对齐之后换掉 Tauri 外壳，删除 `src-tauri`、`src/`（React）和这里对 ui-shell.md 的覆盖说明。

第 1 步已经开始。第 2 步的自动测得的部分做完了（见下面「对比结果」），输入法要在真机上用才知道，还没做。

## 工具包的验收条件

任何候选都要过这几条，过不了就不选：

- **中文输入法**：能输入、能选词、候选窗口跟着光标、能和快捷键共存。
- **许可证**：与 Apache-2.0 的发行方式兼容。已知 Slint 是 GPL-3.0、免版税协议（要署名）或商业三选一，GPL 不能用，免版税协议要项目负责人确认接受。
- **3D 预览**：能接 wgpu 之类，不被界面框架的重绘节奏拖住；开着一个静止的 3D 画面时 CPU 占用接近 0。
- **可访问性**：键盘能走完所有操作；读屏至少能读出控件名。做不到的要写明。
- **外观**：深浅色主题、可以做出现在 Fluent 那样的层次感（不要求像素级一致）。

## 对比结果（2026-10-31）

代码在 `spikes/native-ui/`，不属于启动器的构建（自己的 workspace，提交检查不编译它）。两个候选各做同一件事：用 `aether-app` 列出实例，一个改名表单（输入框里输中文），一个 16×16×16 的方块网格（约 2200 个方块、8 万个顶点，一次实例化绘制，替身 3D 预览），用 wgpu 画。两边共用数据、表单逻辑、方块和量法（`common/`），只有工具包不同。版本：iced 0.14.0（wgpu 27），egui/eframe 0.37.0（wgpu 30）。Slint 没做，原因见下面的许可证一项。

测试机：GTX 1660 SUPER，1920×1080，显示器 59 Hz，Windows 11。**不是目标的 1 核 1 GB 集成显卡，所以下面的帧时间说明不了那一条。** 运行 `spikes/native-ui/bench.ps1` 可以重测，原始输出在 `bench-results.txt`，截图在 `screenshots/`。

| | iced | egui |
| --- | --- | --- |
| 稳态帧率（转动，10 秒，两次） | 59.9 / 59.9 fps | 60.0 / 59.9 fps |
| 帧间隔 p99（含启动） | 21.4 / 21.5 ms | 21.9 / 20.3 ms |
| 帧间隔最大值（含启动） | 22.9 / 22.5 ms | 53.5 / 51.2 ms |
| 超过中位数 1.5 倍的帧 | 0 / 0 | 7 / 4 |
| 稳态 CPU（转动） | 8.3% / 8.0% | 9.1% / 7.8% |
| 静止 3D 画面的稳态 CPU | 0.5% / 0.5% | 0.2% / 0.0% |
| 静止时 10 秒内重绘的帧数 | 0 / 0 | 0 / 0 |
| 内存（工作集，转动 14 秒后） | 约 167 MB | 约 218 MB |
| 发布版体积（未 LTO） | 11.7 MB | 14.0 MB |
| 发布版编译时间（`-j 2`，冷） | 6 分 40 秒 | 7 分 09 秒 |
| 依赖 crate 数 | 467 | 446 |

怎么读：

- **帧率**两边都咬住了垂直同步（60 Hz 的间隔 16.67 ms），转动时都没有掉帧到肉眼可见的程度；差别在抖动：iced 两次都没有超过 1.5 倍中位数的帧，egui 有 4–7 个，最长约 50 ms 的一帧每次都有。这个最长帧是不是出在启动阶段，这里没有分开记，不能说它在稳态里也会出现。每次只有 590–600 个稳态帧、两次运行，差别是迹象，不是定论。
- **静止时**两边都不重绘，CPU 接近 0，满足「静止的 3D 画面 CPU 接近 0」。启动阶段 iced 画了 1 帧，egui 画了 7 帧。
- **内存**是进程工作集，里面有 NVIDIA 驱动映射的主机内存，集成显卡上会不一样；两边相差的 50 MB 方向可信，绝对值不能照搬。
- **3D 接入**：iced 的 `shader` 控件把 wgpu 设备和窗口的渲染目标交给自己，自己开渲染通道、自己管深度缓冲，直接画在窗口里。egui 的渲染通道没有深度缓冲给我们用，所以先画到自己的纹理，再让 egui 当图片贴出来，多一份纹理，缩放时要重建。两边的写法各约 150 行 wgpu，一次就能通过编译，没有碰到工具包的限制。
- **中日文显示**：iced 用系统字体，不用做任何事，中文、日文（サバイバル）都对。egui 不看系统字体，要自己找一个 CJK 字体文件读进来（`msyh.ttc` 等），找不到就显示成方框；Windows、macOS、Linux 要分别写路径，这是要长期维护的东西。
- **输入法**：两边的输入框都有输入法的代码路径（iced 的 `text_input` 和 egui 的 `TextEdit` 都处理预编辑文本，窗口层都设置了输入法区域）。**但谁的候选窗口位置对、选词对、能不能和快捷键共存，没有在真机上用过，不知道。** 这是验收条件里的第一条，必须有人用拼音和五笔各试一遍才能选。
- **许可证**：两边的依赖树都没有只能按 GPL 用的东西。标出来的三个都是双许可、有宽松选项：`r-efi`（只在 UEFI 目标用）、`self_cell`（Apache-2.0 或 GPL-2.0-only，选 Apache-2.0）。iced 是 MIT，egui 是 MIT 或 Apache-2.0。Slint 是 GPL-3.0、免版税协议（要署名）或商业三选一，GPL 不能用，免版税协议要项目负责人确认，所以没做它。
- **可访问性**：egui 带 AccessKit（本次开了 `accesskit` 特性，没有用读屏软件测过）。**iced 0.14 没有可访问性支持**，它的依赖里没有 AccessKit。验收条件写了「做不到的要写明」：选 iced，读屏读不出控件名，键盘能不能走完所有操作要另外验证。
- **外观**：见 `screenshots/`。iced 默认的深色主题比 egui 的默认外观精致，圆角、留白和层次都更接近现在的 Fluent；egui 默认偏工具软件，要做出同样的层次要自己调很多。两者都没有做 Fluent 的令牌映射。
- **API 的稳定性**：写这个对比时，iced 0.14 和 egui 0.37 的 API 都与我记忆里的版本不同（iced 的复选框、egui 的 `show_inside` 改名、wgpu 27 与 30 在好几个结构上不一样），都是按源码改过来的。两者都是每个版本有破坏性改动的库，升级要预留时间。

倾向：**iced**。依据是帧间隔更平稳、内存少、系统字体不用管、3D 直接画进窗口、默认外观更接近要的层次。最大的代价是没有可访问性，这一条要负责人接受。**这个倾向没有包含输入法的结果，输入法实测之前不能定。**

## 待定

- 工具包：iced 还是 egui（见上）。定之前需要：① 在真机上用拼音、五笔输入，看候选窗口位置和选词；② 负责人决定能不能接受 iced 没有读屏支持。
- 在 1 核 1 GB 的集成显卡（或最接近的机器）上再量一次帧时间，否则「集成显卡不掉帧」没有验证。`bench.ps1` 可以直接用。
- 在刷新率更高的显示器上量一次（本机 59 Hz），确认帧预算跟着刷新率走。
- Fluent 设计令牌（`ui-shell.md` 里的颜色、圆角、动效）怎么映射到原生：直接移植数值，还是重新设计。
- Mica 材质：原生窗口可以直接请求，细节看工具包。
- 网站（`site/`）和它的设计规范不受影响，继续用 React。
- 设置、账户等现在存在 `localStorage` 里的东西，原生版要放到应用数据目录里的文件，需要一个迁移。
