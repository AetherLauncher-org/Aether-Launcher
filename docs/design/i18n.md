# 国际化（i18n）设计

> 状态：切片 0（基础设施 + 外壳导航）已落地，见文末「分片迁移计划」。待定项列在「待定」一节，需要维护者拍板。

## 目标与非目标

**目标**

- React UI 与计划中的 Rust 原生 UI 共用同一份语言目录，不重复维护。
- 低端机器上可忽略的加载成本：编译期打包、无运行时网络请求、无额外解析依赖。
- 翻译的完整性和一致性可在 CI 里自动检查，避免「改了中文忘了英文」。

**非目标**

- 不引入 i18next / react-i18next 之类重型库。切片自带一个约一百行的类型化模块。
- 不在这一版做运行时语言检测（跟随系统）——见「待定」。
- 不在这一版翻译后端错误文本——见「Rust 侧错误本地化」。

## 目录与键格式

语言目录放在仓库顶层 `locales/`，一个语言一个 JSON 文件：

```
locales/
  zh-CN.json    # 源语言，也是回退目标
  en-US.json    # 第二语言
```

放在顶层（而不是 `src/` 或 `src-tauri/`）的原因：`docs/design/native-ui.md` 计划删除 `src/` 和 `src-tauri/`，改为 Rust 原生 UI。目录只有放在两者之外，React UI 和未来的 Rust UI 才能共用同一份文件。

**键格式**：扁平、点分命名空间，例如 `nav.account.title`。不用嵌套对象，这样键是一个字符串，`t()` 的查找和 `scripts/check-locales.mjs` 的比对都只需要一层。

**占位符**：`{name}` 形式的 ICU-lite 占位符。规则：

- 只支持 `{name}`，`name` 是 `[a-zA-Z_][a-zA-Z0-9_]*`。
- 不支持 ICU 的 `{count, plural, ...}` 内联选择器，也不支持转义（`'{'`、`''` 等）。多态（复数）用下面「复数（plural-lite）」的外部化方式。
- 未知占位符、缺失参数一律原样保留 `{name}`，让问题在界面上直接可见，而不是悄悄吞掉。

**复数（plural-lite）**：把复数规则从 ICU 内联搬到键名上。一个「复数词干」由多个类别键组成：

```json
{
  "download.fileCount.one": "{count} 个文件",
  "download.fileCount.other": "{count} 个文件"
}
```

调用 `t("download.fileCount", { count: n })`，`t()` 用 `Intl.PluralRules` 按当前语言取类别（`zero`/`one`/`two`/`few`/`many`/`other`），拼出 `download.fileCount.<类别>`；类别缺失时回退到 `<词干>.other`，再走普通回退链。`count` 是保留参数名。

**键命名约束**（`check-locales.mjs` 会校验一部分）：

- 每个值必须是字符串（复数类别也是平铺的字符串键，没有嵌套对象/数组）。
- 非复数键不要以复数类别后缀（`.one`、`.other` 等）结尾，避免和复数词干混淆。
- 一个文件一个键一行，便于 checker 做重复键检查。

## 回退链

源语言（source of truth）是 **zh-CN**，第二语言 **en-US**。查找顺序：

1. 当前语言目录里的键；
2. `zh-CN` 里的同名词干；
3. 键名本身（原样显示，让缺翻译在界面上直接暴露，而不是静默出错）。

选 zh-CN 作为源语言，是因为 Aether Launcher 的界面文本本来就以中文书写，现有文案和测试断言都是中文；把中文定为源语言，缺翻译时回退到中文是「回到现状」而不是「回到空串」。

## 语言检测与设置

**当前切片**：显式设置，默认 `zh-CN`。语言存在 `localStorage` 的 `aether.locale`，读写沿用现有 `aether.*` 设置（`motion`、`theme` 等）的模式——`try/catch` 静默回退到默认值，未知值用类型守卫挡掉。`I18nProvider` 挂载后会把 `document.documentElement.lang` 设为当前语言（`index.html` 已写死 `lang="zh-CN"`）。

**待定（维护者拍板）**：是否加「跟随系统」选项。建议加：读取 `navigator.language`，落进 `zh-CN` / `en-US` 之一，其余语言回退 `zh-CN`；这样和主题已有的「跟随系统」语义一致。本切片先不做，避免和「显式设置」的语义纠缠。

> 存储层要可替换：原生 UI 落地后，设置会从 `localStorage` 挪到应用数据文件。`src/i18n/locale.ts` 的 `load`/`save` 是唯一读写点，替换时只改这一处。

## Rust 侧错误本地化

现状：`crates/aether-app/src` 里约 122 处 `format!("…")` 直接拼英文错误字符串（如 `"cannot retrieve Mojang version catalog: {error}"`），这些错误最终穿过 `Host`/IPC 显示给用户。

**建议（推荐）**：Rust 返回**稳定的错误码**（例如 `MojangCatalogUnavailable`），由 UI 用 `t()` 翻译成文案。理由：

1. **分层正确**。`docs/architecture.md` 里 `aether-app` 是「UI 无关的操作层」，本就不该知道界面语言；翻译属于表现层职责。
2. **原生 UI 可复用**。未来 Rust 原生 UI 同样用 `locales/` 做翻译；错误码方案下，Rust 侧零改动，两种 UI 各自翻译。
3. **可测、可查**。错误码稳定、可 grep、可做完整性检查；文案散在 `format!` 里既难枚举也难保证两种语言一致。
4. **改写成本可控**。122 处虽多，但大多是「出错即中止」的 `anyhow::Error` 包装点；改成返回带 `ErrorCode` 的错误类型，UI 侧按码查表即可。

**备选**：Rust 侧用一个小 crate 读 `locales/` 直接翻译。缺点是与原生 UI 抢职责、把语言状态带进操作层、且两种 UI 的翻译逻辑要维护两遍。仅当需要「无 UI 环境（CLI、日志）也出本地化文案」时才值得。

> 待定：错误码方案的具体形状（`ErrorCode` 枚举 vs 字符串常量、是否带可插值参数）在切片 5 落地前另开讨论。本切片不动 Rust。

## 加载成本（低端机器）

- **编译期打包**：`src/i18n/catalogs.ts` 用 `import zhCN from "../../locales/zh-CN.json"` 静态导入（`tsconfig` 已开 `resolveJsonModule`，Vite 原生支持 JSON import），随主包一起 tree-shake，**没有任何运行时 `fetch`**。
- **无解析依赖**：JSON 由打包器内联，不引入 ICU/MessageFormat 之类的运行时解析库。
- **体量与启动成本**：两份目录随应用一起打包；切片中没有新增第三方依赖。具体压缩体积和低端设备启动耗时尚未测量。普通消息仅做键查找与插值；使用数字 `count` 时才调用内置的 `Intl.PluralRules`。

本切片未引入任何新依赖，因此未做 bundle 体积实测；若未来引入第三方 i18n 库，须先量出增量再定。

## 翻译工作流

新增/维护翻译用 `scripts/check-locales.mjs`，以 `zh-CN.json` 为基准校验其余语言：

- **缺失键**：`zh-CN` 有而目标语言没有；
- **多余键**：目标语言有而 `zh-CN` 没有；
- **占位符不一致**：同一键两边的 `{name}` 集合不一致；
- **复数类别不完整**：出现 `<词干>.<类别>` 却没配 `<词干>.other`（回退类别）；
- **结构错误**：值不是字符串、顶层出现非平铺结构；重复键检查依赖每行一个键，不能保证发现压缩 JSON 中的重复键。

运行方式（本地等价于 CI 检查）：

```powershell
npm run check:locales
```

退出码非 0 表示有问题，stderr 按语言列出差异。新增一种语言 = 新建 `locales/<locale>.json`，并在 `src/i18n/catalogs.ts` 中登记目录、语言列表和显示名。

## 分片迁移计划

目标是把 UI 文案逐片迁到 `t()`，每片一个 PR，让和其他分支的合并冲突尽量小。

- **切片 0（本片）**：基础设施——`locales/` 目录、`src/i18n/` 模块（`t`/`useT`/`I18nProvider`/语言持久化）、`scripts/check-locales.mjs`；外壳导航切到 i18n（`NavPane`、`TitleBar`）；设置页加「界面语言」下拉。
- **切片 1**：设置页整页（外观/内存/Java/登录/下载来源/关于的分节标题与行文案），页头标题与说明。
- **切片 2**：主页 + 实例页（含空状态、卡片）。
- **切片 3**：下载页 + 账户页。
- **切片 4**：对话框与复用组件（`ConvertSchematicDialog`、`ContentBrowser`、日志页等）。
- **切片 5**：后端错误码化 + UI 错误文案（配合「Rust 侧错误本地化」）。

每个切片只改它负责的 `t()` 调用点，不顺手重构组件结构；`navigation.tsx` 的 `PageDefinition` 保持不变，页面文案在**消费点**用 `page.<id>.label` / `page.<id>.summary` 之类的键取，不把键塞进定义。

## 与原生 UI 的共享

- `locales/` 位于 `src/` 之外，原生 UI 落地删除 React 代码后目录仍在。
- 未来加一个 `aether-i18n` Rust crate 读同一批 JSON；`check-locales.mjs` 的「键/占位符一致性」逻辑是共享契约——两边各自保证和 `zh-CN` 对齐即可，不必共用同一份代码。
- 占位符语法 `{name}` 是 ICU 的子集，Rust 侧用 `str::replace` 或轻量模板即可实现等价替换。
